# ADR-0001 — Telegram Mini App — перший інтерфейс; PWA — другий, відкладений

Статус: accepted (2026-09)

## Контекст
ЦА (репетитори, міні-школи) живе в Telegram; вхід без встановлення
застосунку — головна перевага. Водночас Telegram — платформний ризик,
тож незалежний вхід (PWA) колись знадобиться. Паралельна розробка двох
входів подвоює поверхню тестування й деплою заради користувачів, яких
ще нема.

## Рішення
У Ф1 — лише Telegram Mini App. PWA свідомо відкладено. Але інваріанти,
що зроблять PWA дешевою, закладаються з нульового дня:
- авторизація — лише через адаптер: про initData знає тільки
  `src/zoshyt/auth/`; назовні — TeacherId;
- ключ користувача — `teacher_id` (uuid), не `tg_user_id`
  (він nullable — під майбутній magic link);
- кожен екран працює в браузері без Telegram (`AUTH_MODE=dev`);
- Telegram SDK на фронті — за тонким шаром (theme.ts, кнопки), без
  прямих викликів у компонентах екранів.

## Альтернативи (відкинуті)
- PWA паралельно у Ф1 — подвійна робота без користувачів.
- Нативні застосунки / стори — обсяг і релізний цикл поза бюджетом MVP.

## Наслідки
- Дизайн кожного екрана мусить мати стан «відкрито без Telegram».
- MagicLinkAuth — окремим ADR, коли настане тригер.

## Для Claude Code
Жоден код поза `auth/` не читає і не парсить initData. На фронті всі
HTTP-виклики — через `miniapp/src/api/client.ts`, креденшл — лише з
`api/auth.ts`.
