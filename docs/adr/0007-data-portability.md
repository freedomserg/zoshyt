# ADR-0007 — Data portability: експорт власнику — незнімна вимога

Статус: accepted (2026-09)

## Контекст
Урок Всеосвіти + платформний ризик Telegram: дані мають лишатися у
користувача за будь-якої долі сервісу чи платформи. Бекапи (ADR-0006)
цього не закривають — вони наші, а не користувача.

## Рішення
Власник школи завжди може вивантажити ПОВНІ дані свого tenant-а —
сирий CSV з events (з якого відновлюється все). Це продуктова вимога
рівня MVP, не «потім». Канали доставки — ADR-0011.

## Альтернативи (відкинуті)
- «Достатньо бекапів» — не в руках користувача.
- Експорт лише проєкцій (баланси) — не повні дані; допустимий лише як
  додатковий «людський» файл.

## Наслідки
- Формат експорту — стабільний і документований (колонки events).
- Експорт фігурує в дизайні екрана оплат (кнопка).

## Для Claude Code
Експорт — read-only запит до journal, фільтр за school_id власника.
Нічого не пише в events. Одна функція генерації CSV — багато способів
доставки.
