# ADR-0020: Доступ викладачів і запрошення в заклад

**Статус:** Accepted, 2026-09-28. Один пункт — до фідбеку #11 (позначено).
**Спирається на:** ADR-0016 (ролі), ADR-0017 (створення закладу).

## Контекст
Керівник бачить і робить у закладі все. Викладач має бачити лише групи, які йому надав керівник. Людей додають запрошенням; бот не може написати першим тому, хто не натискав Start, тож посилання-запрошення пересилає сам керівник.

## Рішення
- **Доступ = «викладачі групи».** Викладач бачить групу, якщо він серед її викладачів. Окремого поняття «доступ» немає. Для керівника той самий зв'язок означає лише «веде групу».
- **Прапорець «усі групи»** у членстві викладача (`school_members.all_groups`, за замовчуванням false): доступ до всіх наявних і майбутніх груп — для маленьких закладів.
- **Права викладача у своїх групах.** Може: бачити учнів, розклад, історію; відмічати присутність; переносити й скасовувати заняття, сповіщати батьків; нагадувати боржникам своїх груп. Не може: бачити інші групи; створювати групи; змінювати ціни й абонементи; додавати учня в інші групи; керувати людьми; завантажувати CSV.
- **Запис оплати викладачем — до фідбеку #11: не може.** Якщо відповідь «може» — новий ADR, що змінює цей пункт.
- **Картка учня для викладача:** лише його групи; спільна шапка (ім'я, контакт батька, статус бота); загальний грошовий баланс і один рядок «Інші групи: <сума>» без деталей. Цей рядок агрегує сервер — події інших груп викладачу не віддаються.
- **Перевірка доступу — у journal.** Кожен запит і команда отримують область доступу актора: `school_id` + множина груп або «усі». api її лише передає. Недоступна група чи учень → 404, а не 403: не розкривати, що вони існують.
- **Права не кешуються.** Роль і групи визначаються на кожному запиті з поточного стану; «Прибрати доступ» діє з наступного запиту.
- **Запрошення в заклад:** випадковий токен ≥ 128 біт у base64url (у межах 64 символів параметра `start`); у БД — лише хеш токена; одноразове; діє 7 днів; несе роль і, для викладача, групи або «усі». Прийняття: `/start <токен>` → бот → команда journal «приєднатися до закладу». Керівник може скасувати запрошення, поки його не прийняли. Сирого токена немає ні в подіях, ні в логах.
- Надсилання запрошення — з Mini App через вікно Telegram «вибір чату» або копіювання посилання; надсилає керівник зі свого акаунта.

## Альтернативи
- **Доступ до окремих занять** — надто дрібно; заміна колеги закривається тимчасовим додаванням до групи.
- **«Доступ» і «хто веде» як два окремі зв'язки** — дві настройки, які розходитимуться.
- **Фільтрувати доступ в api або лише ховати у фронті** — легко пропустити один ендпоінт.
- **Зберігати токен як є** — дамп БД, бекап чи роль `zoshyt_readonly` видали б робочі запрошення.
- **Багаторазове посилання** — переслане не туди дає доступ стороннім.

## Наслідки
- V2: проєкція «викладачі групи», `school_members.all_groups`, проєкція запрошень (хеш, роль, групи, `expires_at`, стан).
- Тести: матриця «ендпоінт × роль × група з доступом / без» — без доступу завжди 404; прийняття простроченого, використаного, скасованого запрошення; прибраний доступ діє з наступного запиту.
- Посилання для батьків — окремий механізм (ADR про сповіщення батьків, після #11).

## Для Claude Code
- Жодного запиту чи команди journal без області доступу актора.
- Фронт ховає недоступне лише для зручності; межа — у journal.
- Токени — лише як хеш; сирий токен не логувати і не класти в `payload`.
- Недоступне → 404.
