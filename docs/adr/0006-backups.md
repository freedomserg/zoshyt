# ADR-0006 — Бекапи: pg_dump → age → Backblaze B2 + tested restore

Статус: accepted (2026-09)

## Контекст
Журнал містить PII (імена дітей, телефони батьків). Бекап у чужому
сховищі без клієнтського шифрування неприпустимий. Сховище має бути
декорельоване і від VPS-провайдера, і від Cloudflare-акаунта (там уже
домен, DNS, тунелі — спільна точка відмови).

## Рішення
Щодня cron на VPS: `pg_dump -Fc` (образ postgres:17 через compose
exec) → шифрування age (client-side) → rclone у B2. Retention 30 днів
(робить rclone). Успіх → ping HC_BACKUP_URL. age-ключ — у менеджері
паролів обох, не лише на VPS. restore-drill.sh: останній дамп →
розшифрувати → тимчасовий postgres:17 → перевірка count/max →
прибрати; раз до першого реального запису, далі щомісяця.

## Альтернативи (відкинуті)
- Cloudflare R2 — той самий акаунт, що домен/DNS/тунелі: втрата
  акаунта = втрата сервісу І бекапів.
- Snapshot-и Hetzner — той самий провайдер, що VPS.
- Незашифровані дампи — PII. SSE-B2 (дефолт з 09.2026) — шифрування
  ключами провайдера, НЕ заміна age.

## Наслідки
- Версія postgres у compose, CI і restore-drill мусить збігатися (17).
- Object Lock на бакеті не вмикати (конфліктує з retention rclone).

## Для Claude Code
backup.sh і restore-drill.sh — у репо, POSIX shell, без секретів
(значення — з .env на VPS). B2_* змінні існують лише на VPS.
