# ADR-0004 — Бот: aiogram long polling, без webhook попри наявний 443

Статус: accepted (2026-09)

## Контекст
Публічний HTTPS у проєкту і так є (Mini App), тож webhook технічно
доступний з нульового дня — але що він дає?

## Рішення
Long polling. Webhook на нашому масштабі не додає нічого, а коштує:
секрет webhook, обробка повторних доставок, залежність живості бота
від живості HTTP-периметра (ще одна точка відмови).

## Альтернативи (відкинуті)
- Webhook — якщо колись знадобиться (масштаб, latency), окремий ADR
  разом із секретом і ідемпотентністю обробки.

## Наслідки
- Процесу bot не потрібен published port.
- getUpdates конфліктує з двох місць → один процес на токен; звідси
  окремі dev-боти (@zoshyt_dev_s_bot, @zoshyt_dev_k_bot) і prod
  (@zoshyt_app_bot).

## Для Claude Code
Не створювати webhook-роутів в api. Бот — окремий процес
(`python -m zoshyt.bot`), не частина api.
