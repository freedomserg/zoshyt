# ADR-0011 — Канал експорту даних власнику

Статус: accepted (2026-09-08)

## Контекст
Data portability — незнімна вимога (ADR-0007): дані мають лишатися
у користувача за будь-якої долі сервісу або Telegram. Кандидати на
канал доставки: (а) CSV файлом у Telegram, (б) email через
Resend/Brevo. Формулювання «за будь-якої долі Telegram» містить
суперечність для варіанта (а): пуш через Telegram не працює саме
в момент, коли Telegram зник.

## Рішення
Носій вимоги portability — не пуш, а ПУЛ: кнопка «завантажити CSV»
у Mini App, обов'язкова частина MVP. Файл опиняється на пристрої
власника, поза Telegram і поза сервісом.

Пуш-канал у Ф1 — CSV файлом у Telegram (щотижнева джоба):
найдешевший, нуль нових акаунтів, роль — нагадування-звичка
(«у тебе є свіжа копія»), не гарантія.

Email-пуш — за тригерною умовою «перша школа поза design-partner»:
тоді з'являється користувач, чиїй дисципліні скачувати не можна
довіряти. До того SMTP_* в env не заводиться.

Формат: сирий CSV з events (повні дані, з яких відновлюється все).
Опційно другий, «людський» CSV з балансами; сирий журнал — обов'язковий.

## Альтернативи (відкинуті)
- Email одразу в MVP: ще один акаунт і секрети, SPF/DKIM на домені,
  а головне — вимагає збирати email викладача, тобто розширює PII
  (суперечить ADR-0009) заради каналу, який Ф1 не потребує.
- Лише пуш у TG без кнопки: не закриває portability — у момент
  катастрофи каналу доставки нема.

## Наслідки
- Крок 1 без змін: SMTP_* не додається.
- ADR-0009 без змін: email-поля в схемі нема. Коли прийде email-пуш —
  окремий ADR (Supersedes) з email як опційним полем.
- Розблоковано дизайн екрана оплат для [CD]: кнопка «експорт CSV»,
  без налаштувань пошти.
- Свідомо прийнятий ризик для design-partner: вікно між зникненням
  Telegram і останнім скачаним файлом.

## Для Claude Code
Експорт — read-only запит до journal. Одна функція генерації CSV,
два способи доставки: api (кнопка в Mini App) і bot (щотижнева
APScheduler-джоба, файл власнику в TG). Нічого не пише в events.
