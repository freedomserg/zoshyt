# ADR-0017: Заклад — термін, тип, створення через онбординг

**Статус:** Accepted, 2026-09-28

## Контекст
ЦА ширша за школи: гуртки, студії, центри, приватні заняття. Керівник при створенні обирає тип закладу, вводить назву і своє ім'я (бриф мокапів, 01-onboarding). У плані кроку 5 `/start` → `RegisterTeacher` створює викладача, школу й членство.

## Рішення
- **Термін.** В UI — «заклад» + його тип; у коді й БД — `school` / `school_id` без перейменування (tenant-колонка в кожному запиті, таблиця на prod). Рядок у глосарії CLAUDE.md: «school у коді = заклад в UI».
- **Тип.** У `schools`: `kind text NULL` з `CHECK (kind in ('school','club','studio','correctional_center','development_center','private_lessons','other'))` і `kind_custom text NULL`; `CHECK ((kind = 'other') = (kind_custom IS NOT NULL))`. Ключі англійською — стабільні; підписи в UI — українською, лише в називному відмінку.
- **Створення — варіант (б).** `/start` без запрошення → `RegisterTeacher` як у кроці 5: викладач + заклад з назвою-заготовкою «Мій заклад», `kind = NULL` + членство `owner` + подія. Онбординг Mini App → команда, що задає тип, назву і `display_name` — подія зміни профілю закладу; та сама подія — для пізніших правок у налаштуваннях.
- **`kind IS NULL` = онбординг не завершено**: Mini App показує онбординг, доки тип не задано. Окремого прапорця немає.
- `/start` за посиланням-запрошенням заклад не створює — лише приєднує (деталі — ADR-0020).
- `display_name` — як у V1: з профілю Telegram при `/start`, редагується в онбордингу.

## Альтернативи
- **(а) `/start` лише реєструє викладача, заклад — першою командою з UI.** Tracer bullet (M1) тоді мусив би мати ланцюг UI → journal, від якого свідомо відмовились. Відкинуто.
- **Перейменувати `schools` → `venues`** — ціна (prod, кожен запит, міграції, тести) без користі.
- **Тип лише вільним текстом** — не порахувати, скільки гуртків і студій. **ENUM Postgres** — важче змінювати, ніж `text + CHECK`.

## Наслідки
- V2-ревізія: `kind`, `kind_custom`, два CHECK; рядки V1 отримують `kind = NULL` (онбординг покажеться).
- M1 не змінюється: tracer bullet пише в journal лише з бота. Команда онбордингу — перший ланцюг UI → journal, на початку M2.
- Якщо користувач закрив Mini App до кінця онбордингу — заклад лишається «Мій заклад» до наступного відкриття. Прийнято.

## Для Claude Code
- В UI-текстах ніколи «школа» як назва сутності; тип — лише підписом у називному відмінку.
- Не перейменовувати `school_id`, `schools`.
- Список ключів `kind` — одне місце в коді (journal), UI бере підписи з мапи.
