# ADR-0016: Кілька керівників закладу; роль ≠ викладання

**Статус:** Accepted, 2026-09-28
**Змінює:** рішення схеми V1 «один власник на школу» (індекс `one_owner_per_school`, ревізія `20260919_1`). Ревізія не редагується — зміна новою ревізією.

## Контекст
Заклад можуть вести кілька рівноправних партнерів. Керівник не обов'язково веде заняття: засновник центру може лише адмініструвати. V1 дозволяє рівно одного `owner` на школу.

## Рішення
- Дві ролі, як і раніше: **керівник** (`role = 'owner'`) і **викладач** (`role = 'teacher'`). Керівників ≥ 1, права однакові.
- В UI — «Керівник» / «Викладач». У коді й БД лишається `owner`: це ідентифікатор, не текст інтерфейсу.
- **Інваріант «≥ 1 керівник»** перевіряє journal у командах, що прибирають або понижують керівника (зняти роль, прибрати доступ, вийти самому). Команди tenant-а вже серіалізуються row lock-ом на `schools` (видача `seq`), тож дві паралельні команди «керівники знімають одне одного» не пройдуть обидві.
- Керівник може прибрати чи понизити іншого керівника; подія з `actor_teacher_id` — видно, хто і коли.
- **Роль визначає права; хто веде групу — окремий зв'язок «викладачі групи»** (ADR-0020). Керівник може бути в ньому або ні. Для ролі «Викладач» цей зв'язок водночас є доступом.
- V2-ревізія: `DROP INDEX one_owner_per_school`. `CHECK (role in ('owner','teacher'))` без змін.

## Альтернативи
- **Один власник + «адміністратори» для партнерів** — нерівноправність і третя роль; Контекст обмежує ролі двома.
- **Інваріант тригером у БД** — «хоча б один» не виражається простим обмеженням; тригер — логіка поза journal, яку важче тестувати й читати.
- **Третя роль «керівник-викладач»** — множення ролей; розв'язується окремим зв'язком «викладачі групи».

## Наслідки
- Тест (г) «другий owner → помилка» замінюється тестами команд: останнього керівника не прибрати / не понизити / не вийти; паралельні спроби — одна проходить.
- Ризик: партнер може відрізати іншого від даних. Прийнято; історія подій це показує. Питання — у #11.
- Будь-який керівник може завантажити CSV (ADR-0007, ADR-0011).

## Для Claude Code
- Ніде не припускати «один owner»: керівники — список `role = 'owner'`.
- Інваріант — лише в командах journal, не в api і не в БД.
- Не перейменовувати `owner` у БД/коді; «Керівник» — лише в UI.
