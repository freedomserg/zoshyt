# ADR-0008 — Без прийому платежів у MVP

Статус: accepted (2026-09)

## Контекст
Біль ЦА — облік оплат і нагадування, не сам прийом грошей. Еквайринг
тягне юридику, комісії, онбординг провайдера і чутливі дані.

## Рішення
Оплати — лише ручна фіксація викладачем: подія PaymentRecorded
(сума, учень, період). Баланс — проєкція з подій. Помилки — компенсація
(PaymentCancelled).

## Альтернативи (відкинуті)
- Інтеграція еквайрингу (mono, LiqPay, …) — складність і зобов'язання
  без жодного запиту від користувачів; свідомо поза MVP.

## Наслідки
- Жодних платіжних SDK і PCI-міркувань у кодовій базі.
- Якщо колись — окремий ADR; append-only журнал уже готовий до
  зовнішніх платіжних подій.

## Для Claude Code
Не додавати платіжні залежності/інтеграції. Суми — integer у копійках,
валюта — поле події (у MVP — 'UAH').
